# 認証仕様（ログインの状態の管理）

> **状態: 下書き**（plan 5.6 の 4、2026-11-28）。ログインが保たれる期間と、最小化したまま SSO が切れたときの画面は PoC-8 で確かめ、その結果で確定する（plan 5.6 の 6）。

## 1. 範囲と方針

- llmc がチャットのサイトにログインした状態を保ち、切れたことを検知し、利用者にログインし直してもらう手順を定める
- **ログインは利用者が行う**。llmc は資格情報を入力しない、保存しない。MFA の秘密鍵を保存して自動でログインすること（類似の実装にある）はしない（review-related-projects 4 章）
- 組織の条件付きアクセス・ポリシーを回避しない（ヘッドレスの禁止と同じ方針）
- 対象: 自動の方式（llmc のプロセスが動かす Edge。spec-runtime）。人が送信する方式は、利用者がふだん使うブラウザでログインしているので、llmc は関わらない

## 3. 状態と判定

| 状態 | 意味 |
|---|---|
| `unknown` | まだ確かめていない（ブラウザを起動する前） |
| `logged_in` | 入力欄（プロファイルの `selectors.ready`）があり、ログインの画面ではない |
| `resumable` | サインインのボタンがある。押せば黙ってログインできる見込み |
| `login_required` | ログインの画面（`login.url_patterns`）に転送された、資格情報の入力を求められた、または自動の再ログインが失敗した |
| `blocked` | 条件付きアクセスなどで拒否された表示（`login.blocked_patterns`）。利用者にも直せない恐れがあるので、管理者への確認を案内する |

- 判定するとき
  - ブラウザの起動の後
  - 送信の**前**（URL がログインの画面に一致しないか、入力欄があるか。数十ミリ秒で済む確かめ方にする）。送信の後に切れていたことが分かると、送ったかどうか分からなくなるため
  - 送信がエラーになったとき（ログインの画面への転送が原因でないか）
  - `llmc doctor` と、セッションの `/status`
- サイト別プロファイル（spec-browser-driver 3.2）

```yaml
login:
  url_patterns: ["^https://login\\.microsoftonline\\.com/", "^https://login\\.live\\.com/"]
  selectors: []                       # ログインを促す表示（画面の中のもの）
  resume:                             # 自動の再ログイン（5 章）
    button: ["role=button[name=/Sign in|サインイン/]"]
    wait_ready_s: 45
  blocked_patterns: ["/アクセスできません|You cannot access this right now/"]   # 仮
  credential_patterns: ["input[type=password]", "input[type=email]"]          # 資格情報の入力（ここで止まったら login_required）
```

## 4. `llmc login`

- 利用者がログインし直すためのコマンド。対話のセッションの中では `/login`。単発の `llmc login` は、ブラウザを開いてログインの後に閉じる（プロファイルにログインが残る）
- 動き
  1. 送信中でないことを確かめる（同時に動く llmc は 1 つなので、他の送信と重ならない。spec-runtime 3 章）
  2. ブラウザのウィンドウを元に戻し（`Browser.setWindowBounds` で `normal`）、前面に出す
  3. サイトの `url` を開く
  4. `logged_in` になるまで待つ（上限 10 分）。この間、llmc は画面に何も入力しない
  5. ログインできたら、ウィンドウを最小化する（単発の `llmc login` なら閉じる）
- 「開いた Edge のウィンドウでログインしてください。終わると自動で最小化します」と示し、待つ。Ctrl+C で待ちをやめる
- 初回: プロファイルが無ければ作る。初回も同じ手順

## 5. 自動の再ログイン

- `resumable` のとき、`login.resume.button` を押し、`wait_ready_s` の間 `logged_in` になるのを待つ
  - なれば、そのまま続ける（記録だけ残す。`W_RELOGIN`）
  - 資格情報の入力（`credential_patterns`）が出たら止め、`login_required` にする。**何も入力しない**
- 1 回の送信で試すのは 1 回だけ
- 組織版で `resumable` に当たる画面があるかは PoC-8 で確かめる

## 6. ログインが切れたとき

| 実行 | 動き |
|---|---|
| 対話（`llmc chat`・`llmc ask` を端末から） | 「ログインが切れました。`llmc login` を実行するか、Enter でここからログインの画面を開きます」と示す。ログインできたら、その要求を送る（まだ送っていないので、重ならない） |
| 非対話（パイプ、`--non-interactive`、スケジューラ） | 送らずに `LoginRequired` で終える。終了コード `EXIT_LOGIN_REQUIRED`（spec-shell-integration） |
| ループの途中 | ラウンドの書き込みの前なら、そのラウンドを中断として記録し止める。`llmc login` の後に `--resume` で続けられる（spec-loop 10.3） |

- `login_required` の間、セッションの中の送信は、ログインし直すまで即座に `LoginRequired` にする（spec-browser-driver 11 章）

## 7. ログインの保持（PoC-8 で確かめる）

**運用: 1 日 1 回、利用者が手動でログインする**（plan 前提 18。業務で毎日 Copilot Chat を使うため）。ログインが何日も保たれるかは確かめず、llmc にもそれを延ばす仕組みは作らない。llmc に要るのは、切れたことを送信の前に見つけて `llmc login` を案内すること（3〜6 章）だけ。

| 項目 | 確かめること |
|---|---|
| 朝の画面 | 前の日にログインしたプロファイルを朝に開いたとき、`logged_in`・`resumable`・`login_required` のどれになるか。そのときの画面（ログインの画面への転送か、サインインのボタンか）を判定の規則（`login` の YAML）に使う |
| 1 日の間 | 朝にログインしてから、その日の終わりまで `logged_in` が続くか（PoC-8 の (a)(b) の常駐の記録で分かる） |
| 最小化したまま切れたとき | どの画面になるか（ログインの画面への転送、画面の中の表示、何も変わらず送信が失敗する） |
| 別の user-data-dir | Playwright 用のプロファイル（ふだんの Edge と別）が、ポリシーで拒否されないか。Windows のアカウントでの SSO（デバイスの情報）が効くか |
| 1 日開いたままのとき | 対話のセッションでブラウザを 1 日開いたままにした場合に、ページを読み直す必要があるか |

- 結果によって、決めること
  - 定期的にページを読み直すか（例: アイドルが 1 時間続いたら読み直して判定する）
  - `llmc doctor` で示す「最後にログインを確かめた時刻」

## 8. プロファイルの保護

- 置き場所: `%LOCALAPPDATA%\llmc\profiles\<site>\`。ローミングで同期されない。作るときに、本人と SYSTEM だけの権限にする（継承を切る）
- プロファイルには SSO の Cookie がある。**llmc は Cookie を読まない、書き出さない、ログに書かない**
- `llmc logout <site>`: そのサイトのブラウザを閉じ、プロファイルを消す（確認を求める）
- バックアップ・同期のツール（OneDrive の既知のフォルダーの移動など）の対象外であることを `llmc doctor` で確かめる（`%LOCALAPPDATA%` は既定で対象外）
