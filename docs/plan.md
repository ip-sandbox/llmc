## 2. 参考実装レビューの要旨

詳細は `review-reference-impl.md`。キックオフ資料の問題点 13 件はすべてコードで確認した。さらに、次の追加指摘がある（抜粋）。

- 続きの依頼を上限まで使っても切れたままの回答を適用してしまう
- 自分のメッセージを回答として取り出すと、元の内容を書き戻しただけで「成功」に見える
- `conftest.py` や `pytest.ini` を AI が書くことで、変更禁止をすり抜けてテストを無効化できる
- Playwright のタイムアウトが捕まえられず、終了コード 1（最大ラウンド到達）と区別できない
- パイプ出力時に cp932 で `✅` を出力しようとして異常終了する
- テスト実行にタイムアウトが無い、undo が AI の新規ファイルを消さない、など

## 3. 設計上の主要論点（各仕様書で比較・確定する）

1. **ファイル書式**: メタ情報はフェンスの info 文字列に置く。フェンスは可変長にする。ファイルごとの完全性は、LLM が正確に数えられない行数の申告ではなく、**リクエストごとの nonce を含む終了行をフェンスの内側に置く**方式を第一候補とし、行数は補助にする
2. **回答の特定**: DOM 上の発言者の属性を主に使い、nonce の書き返しを補助にする（自分のメッセージにも nonce が含まれるため、nonce だけでは判別できない）
3. **抽出**: コピーボタン（生の Markdown）を第一候補、DOM からの復元を次善の策とする。DOM 復元の場合は、ファイルごとの終了行が無いブロックを書き込まない
4. **ロールバック**: git に依存せず、run ディレクトリに元のバイト列を保存して戻すことを基本にする。git 連携は worktree を使う任意の機能にする
5. **実行器**: ループのコマンドはシェルを介さず引数リストで直接起動するのを既定とし、タイムアウトとプロセスツリーの強制終了を必須にする
6. **IPC**: 現在のユーザーだけに ACL を絞った名前付きパイプを第一候補にする
7. **シェル**: PowerShell 5.1 と cmd.exe の文字コードの扱いを比較して決める（1 章の 4）
8. **非対話モードと確認の衝突**: 1 章の 5 のとおり
