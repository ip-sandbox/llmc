## 2. 参考実装レビューの要旨

詳細は `review-reference-impl.md`。キックオフ資料の問題点 13 件はすべてコードで確認した。さらに、次の追加指摘がある（抜粋）。

- 続きの依頼を上限まで使っても切れたままの回答を適用してしまう
- 自分のメッセージを回答として取り出すと、元の内容を書き戻しただけで「成功」に見える
- `conftest.py` や `pytest.ini` を AI が書くことで、変更禁止をすり抜けてテストを無効化できる
- Playwright のタイムアウトが捕まえられず、終了コード 1（最大ラウンド到達）と区別できない
- パイプ出力時に cp932 で `✅` を出力しようとして異常終了する
- テスト実行にタイムアウトが無い、undo が AI の新規ファイルを消さない、など

## 3. 設計上の主要論点（各仕様書で比較・確定する）

1. **ファイル書式**: メタ情報はすべてコードブロックの内側の行に置き、info 文字列（言語名）は書かせない（PoC で、Copilot のコピーの HTML が崩れると分かったため）。フェンスは可変長にする。ファイルごとの完全性は、行数の申告ではなく、**ターンごとの ID を含む終了行をフェンスの内側に置く**方式とする。提案全体の完全性は、回答の冒頭の計画（項目の一覧）で確かめる（spec-file-protocol で確定）
2. **回答の特定**: DOM 上の発言者の属性を主に使い、nonce の書き返しを補助にする（自分のメッセージにも nonce が含まれるため、nonce だけでは判別できない）
3. **抽出**: コピーボタンを第一候補（Copilot では、コピーの HTML を区分に分けて解析する。`text/plain` はフェンスが消えるため使わない）、DOM からの復元を次善の策とする。DOM 復元の場合は、ファイルごとの終了行が無いブロックを書き込まない
4. **ロールバック**: git に依存せず、run ディレクトリに元のバイト列を保存して戻すことを基本にする。git 連携は worktree を使う任意の機能にする
5. **実行器**: ループのコマンドはシェルを介さず引数リストで直接起動するのを既定とし、タイムアウトとプロセスツリーの強制終了を必須にする
6. **IPC**: 現在のユーザーだけに ACL を絞った名前付きパイプを第一候補にする
7. **シェル**: PowerShell 5.1 と cmd.exe の文字コードの扱いを比較して決める（1 章の 4）
8. **非対話モードと確認の衝突**: 1 章の 5 のとおり

## 5. 作業の進め方（PoC を挟む）

### 5.1 方針

- 書いた設計書（requirements、architecture、spec-file-protocol、spec-browser-driver、spec-agent）は**暫定版**とする。実物で確かめる仮説を 5.2 にまとめ、PoC の結果で確定・修正する
- PoC は `poc/` に置く使い捨てのプログラム。本体の設計や品質の基準は適用しない
- 分担: PoC を書き、模擬ページなどで動くところまで確かめるのは Claude。実機（Windows の PC と Copilot）での実行は利用者。結果のレポートをチャットに貼ってもらい、Claude が設計書に反映する
- 後続の仕様書は、関係する PoC の結果が出てから書く
- **確認と設計を交互に行う**（5.6）。各仕様書は、まず下書きを書いて「実物で確かめないと決められない項目」を洗い出し、その項目だけを小さな PoC で確かめてから確定する

### 5.2.1 個人の Copilot（copilot.microsoft.com）の結果を、組織にどこまで当てはめられるか

無料の Copilot は、組織の Microsoft 365 Copilot Chat（`m365.cloud.microsoft`）とは別の製品で、画面・ログイン・機能が違う。そのため PoC の結果は、次のように扱う。

| 仮説 | 個人の Copilot で分かること | 組織で改めて確かめること |
|---|---|---|
| H-01（ログイン） | persistent context でのログインの保持と、ヘッドレスでの再利用の仕組みが働くか。ボット対策で止められるか | Entra ID の SSO と条件付きアクセス（PoC-1b）。**ここが本命** |
| H-02〜H-07（画面） | ドライバの方式（入力の読み戻し、ID による回答の特定、完了の信号の組み合わせ、クリップボードの横取り、DOM の抽出）が**仕組みとして**働くか。サイト別プロファイルの形式が足りるか | セレクタの値と、各方式が組織の画面でも働くか（PoC-2b）。セレクタの値そのものは引き継げない |
| H-08・H-09（書式） | AI が書式 llmc/1 を守れるかの**目安**。書式の規則の文面の改善 | 組織の Copilot での守られ方（モデルや指示の違いで変わり得る）。エージェントあり・なしの比較 |
| H-18・H-19 | 対象外（エージェントビルダー、職場と Web の切り替えは組織にしかない） | PoC-5、PoC-2b |

PoC-1 の一部（未ログインでの表示）で、`copilot.microsoft.com` は `copilot.com` に転送され、ログインが前提であることが分かった（docs/poc-findings.md）。組織と同じく、ログインした状態で PoC を行う。

PoC の結果と設計への影響は `docs/poc-findings.md` にまとめる。
